# 소리누리 오디오 스펙트럼 시각화 기획안

**버전**: v2.1 예정  
**작성일**: 2026-07-29  
**상태**: 기획 확정 전

---

## 1. 개요

오디오 스펙트럼 시각화는 재생 중인 오디오 신호의 주파수 성분을 실시간으로 화면에 표시하는 기능이다. 단순한 시각적 효과를 넘어, **돌비 Atmos / DTS-HD MA / TrueHD 등 고품질 오디오의 채널별 에너지 분포를 직관적으로 확인**할 수 있는 전문 모니터링 도구로 설계한다.

---

## 2. 목표 및 사용 시나리오

### 2.1 핵심 목표

| 목표 | 설명 |
|:---|:---|
| **오디오 품질 시각화** | 패스스루(THRU) 상태에서도 디코딩 없이 신호 레벨 모니터링 |
| **채널 분리 확인** | 5.1 / 7.1 각 채널(FL, FR, C, LFE, SL, SR)의 독립 레벨 표시 |
| **주파수 분석** | 저음(20~200Hz), 중음(200Hz~4kHz), 고음(4kHz~20kHz) 대역별 에너지 분포 |
| **음향 설정 피드백** | 화면 필터(EQ) 조정 시 즉각적인 주파수 변화 확인 |

### 2.2 사용 시나리오

**시나리오 A — 패스스루 확인**: 넷플릭스 Dolby Atmos 재생 중 스펙트럼이 활성화되면 패스스루가 정상 동작하고 있음을 시각적으로 확인할 수 있다.

**시나리오 B — 채널 밸런스 점검**: 5.1 채널 영화 재생 시 각 채널의 레벨이 균등한지 확인하고, 특정 채널이 약하거나 없는 경우 즉시 파악할 수 있다.

**시나리오 C — 음악 감상**: FLAC / DTS 음악 파일 재생 시 스펙트럼 애니메이션을 감상하면서 음악의 주파수 특성을 시각적으로 즐긴다.

## 3. 기술 구현 방식

### 3.1 데이터 소스 선택

MPV에서 오디오 데이터를 추출하는 방법은 세 가지가 있다.

| 방식 | 장점 | 단점 | 채택 여부 |
|:---|:---|:---|:---:|
| `lavfi` 필터 (`showcqt`, `showspectrum`) | 구현 간단, MPV 내장 | 영상 위에 렌더링되어 UI 통합 어려움 | 보조 |
| `audio-out-params` + 커스텀 필터 | 정확한 PCM 데이터 접근 | 패스스루 시 데이터 없음 | 부분 |
| **`af=lavfi=[asplit]` + 소켓 IPC** | UI와 완전 분리, 채널별 접근 | 구현 복잡도 높음 | **주 방식** |
| **MPV `observe_property` + `audio-pts`** | 간단, 실시간 | 레벨 데이터만 가능 | **보조 방식** |

**결정**: 소프트웨어 디코딩 시에는 `lavfi` 필터로 FFT 데이터를 추출하고, 패스스루(THRU) 시에는 `audio-pts` 기반 레벨 미터로 대체한다.

### 3.2 FFT 처리 파이프라인

```
MPV 오디오 출력
    │
    ├─ [소프트웨어 디코딩 모드]
    │   af=lavfi=[asplit=2[a][b],[b]showwaves]
    │   → PCM 버퍼 → Qt 스레드 → FFT (FFTW3 또는 KissFFT)
    │   → 주파수 빈 배열 (512개) → 스펙트럼 렌더링
    │
    └─ [패스스루 모드 (THRU)]
        audio-out-params/volume-max 관찰
        → 채널별 레벨 미터 (VU Meter) 렌더링
```

### 3.3 렌더링 방식

Qt의 `QOpenGLWidget`을 활용하여 스펙트럼을 GPU에서 직접 렌더링한다. 이는 소리누리의 기존 `MpvWidget`과 동일한 방식으로, 60fps 부드러운 애니메이션을 보장한다.

```
SpectrumWidget (QOpenGLWidget)
    │
    ├─ BarRenderer: 막대 그래프 (기본 모드)
    ├─ WaveRenderer: 파형 표시 (파형 모드)
    ├─ CircleRenderer: 원형 스펙트럼 (원형 모드)
    └─ ChannelMeter: 채널별 VU 미터 (패스스루 모드)
```

## 4. UI/UX 설계

### 4.1 표시 위치 옵션

스펙트럼은 세 가지 위치에 표시할 수 있으며, 사용자가 선택한다.

| 위치 | 설명 | 기본값 |
|:---|:---|:---:|
| **하단 오버레이** | 영상 하단 20% 영역에 반투명으로 오버레이 | ✓ |
| **독립 패널** | 오디오 정보바 아래 별도 패널 (높이 80px) | |
| **전체 화면 배경** | 영상 없을 때 전체 화면에 스펙트럼 표시 | |

### 4.2 시각화 모드

```
[막대] [파형] [원형] [채널미터]  ← 우클릭 메뉴 또는 V 키로 전환
```

#### 모드 1 — 막대 그래프 (Bar Spectrum)

- 주파수 빈 64개 또는 128개 막대
- 각 막대: 하단에서 상단으로 채워지는 그라데이션
  - 저음(20~200Hz): 파란색 `#1565c0`
  - 중음(200Hz~4kHz): 청록색 `#4fc3f7`
  - 고음(4kHz~20kHz): 흰색 `#ffffff`
- 피크 홀드: 막대 최고점에 1~2초간 흰 선 유지 후 천천히 하강
- 배경: 반투명 검정 `rgba(0,0,0,0.6)`

#### 모드 2 — 파형 (Waveform)

- 실시간 PCM 파형을 좌/우 채널로 분리 표시
- 좌 채널: 파란색, 우 채널: 청록색
- 중앙선 기준 대칭 표시

#### 모드 3 — 원형 스펙트럼 (Circular)

- 원형 배치의 주파수 막대
- 중앙에 소리누리 로고 표시
- 음악 감상 모드에 적합

#### 모드 4 — 채널 VU 미터 (Channel Meter)

- 패스스루 모드 전용
- FL / FR / C / LFE / SL / SR 채널별 수직 레벨 미터
- 각 채널 레이블 표시
- 클리핑 경고: 0dBFS 초과 시 빨간색

### 4.3 컨트롤 UI

```
[스펙트럼 ON/OFF]  [막대▼]  [불투명도: ████░░ 60%]  [색상: ●]
```

- 전문 기능 패널(ProFeaturesWidget) 내에 스펙트럼 섹션 추가
- `V` 키로 모드 순환 전환
- `Ctrl+V`로 스펙트럼 전체 ON/OFF

## 5. 성능 고려사항

### 5.1 CPU 부하 최소화

| 항목 | 목표값 |
|:---|:---|
| FFT 처리 스레드 CPU 사용률 | < 2% (512-point FFT, 60fps) |
| 렌더링 GPU 사용률 | < 1% (OpenGL 막대 그래프) |
| 패스스루 모드 추가 부하 | 0% (레벨 데이터만 관찰) |

### 5.2 스레드 구조

```
메인 스레드 (UI)
    │
    ├─ MpvThread (MPV 이벤트 루프)
    │   └─ 오디오 데이터 콜백 → AudioBuffer (링 버퍼)
    │
    └─ SpectrumThread (FFT 처리)
        └─ AudioBuffer 읽기 → KissFFT → 주파수 빈 배열
            → 메인 스레드 emit → SpectrumWidget 렌더링
```

### 5.3 패스스루 모드 처리

패스스루(THRU) 상태에서는 MPV가 오디오를 디코딩하지 않고 비트스트림을 그대로 전달하므로 PCM 데이터에 접근할 수 없다. 이 경우:

- `audio-out-params/volume-max` 속성을 관찰하여 전체 레벨 표시
- 채널별 레벨은 표시 불가 → "패스스루 모드 — 채널 레벨 미터 비활성" 안내 표시
- 대신 비트스트림 포맷 정보(DTS-HD MA / TrueHD Atmos 등)를 스펙트럼 영역에 텍스트로 표시

## 6. 구현 일정

| 단계 | 작업 내용 | 예상 소요 |
|:---|:---|:---:|
| **1단계** | KissFFT 라이브러리 통합, AudioBuffer 구현 | 1일 |
| **2단계** | SpectrumWidget (막대 모드) 구현 | 1일 |
| **3단계** | MPV 오디오 콜백 연결, 실시간 데이터 파이프라인 | 1일 |
| **4단계** | 파형/원형/채널미터 모드 추가 | 1일 |
| **5단계** | ProFeaturesWidget 통합, 단축키 연결 | 0.5일 |
| **6단계** | 패스스루 모드 처리, 성능 최적화 | 0.5일 |

**총 예상 기간**: 5일

## 7. 의존성

| 라이브러리 | 용도 | 라이선스 |
|:---|:---|:---|
| **KissFFT** | FFT 연산 (헤더 온리, 경량) | BSD-3-Clause |
| **Qt OpenGL** | GPU 렌더링 (기존 사용 중) | LGPL |
| **MPV libmpv** | 오디오 데이터 소스 (기존 사용 중) | LGPL |

KissFFT는 단일 헤더 파일(`kiss_fft.h`, `kiss_fft.c`)로 구성되어 있어 외부 빌드 시스템 없이 소스에 직접 포함할 수 있다.
